# Screenshots

The screenshots in this folder are used by [`README.md`](../../../README.md) (the top-level
project README). Every one of them is generated against real, on-screen PrivacyFence UI — not
mocked up by hand — so re-running the same command reproduces the same image.

`gmail-read-thread.png` and `sheets-write.png` were originally generated by driving a real click
against the real native macOS approval popup (`qa_popup_smoke.py`, a script P10 retired along with
that popup itself — see `docs/https-connector-refactor-plan.md` §12, decision D6). They're still
current: `approval_window_html.py` — the pure HTML the popup used to render — is unchanged, and now
serves the same card content over the web instead. There is no dedicated regeneration script for
them yet; the fastest path is `scripts/qa_web_smoke.py`'s own `_register_card`-style approach,
pointed at whichever tool call you want a card for, screenshotting the `.pf-card` element instead
of driving assertions against it.

`settings-connectors.png` and `settings-auto-accept-rules.png` are generated by
[`scripts/qa_readme_screenshots.py`](../../../scripts/qa_readme_screenshots.py) — the web-settings
replacement for what `menubar.png`/`menubar-auto-accept-rules.png` used to show before P10 deleted
the native menu bar and its own Auto-accept Rules window:

```bash
.venv/bin/pip install playwright   # once, locally -- not committed
.venv/bin/python scripts/qa_readme_screenshots.py
```

Requires `playwright` and a Chromium binary (see `scripts/qa_web_smoke.py`'s own docstring for
where to point `--chromium-path` if none is auto-discovered) — no macOS, no Accessibility
permission, no on-screen window: it drives a real embedded HTTP server + real headless browser, the
same posture `qa_web_smoke.py` uses for its own scenarios. The script seeds a small, representative
fake state (a few connectors marked connected, a handful of Gmail auto-accept rules) so the
screenshots show a populated page rather than every field empty; it never touches a real account.

Only the files actually referenced by `README.md` belong in this folder — it's a documentation
asset directory, not a general QA archive. If you regenerate a screenshot and no longer need the
old one, delete it rather than leaving it behind unused.
